Craftax 3D: component map

The main parts of the game, what each owns and how they connect, read from the code as of 2026-10-29. The rules run in the craftax-wasm engine; everything here draws the game, takes your input, and lets plugins add themes, set pieces, bots and services without editing the game. The directory tree, file by file, is on folders.html.

1. The map

plugins and setup game core engine and bots game parts replay slot: a plugin slot read here

How a move flows: Input (or a bot) picks one Craftax action → the core's api posts it to /api/step → js/local.ts steps the wasm engine in the tab and returns the new state → apply.ts diffs it against the old one and sets off what follows (world rebuild, creatures, effects, sounds, HUD) → frame.ts draws it every frame in the current view and look, under the current theme. Arrows inside the panel: themes feed the world (tiles, heights, decorations) and the renderer (the texture atlas and blend); set pieces draw through the themes' Draw kit; views pick the look, and the look picks the render pass.

3. The actual objects

What exists when the game runs. Most of the code is modules of plain functions, so there are few objects. Nine class instances last as long as the page: the four marked "= new", the four effects, and events, which isn't drawn. One Worker runs per bot model picked. The other boxes are plain objects, three.js objects, or the two functions everything hangs off. Colors follow the map above; a dashed box comes from another repo or a plugin.

What's left out: events (new Events, src/core/events.ts), the short-lived Geo mesh builders, and every mob and shot, which are three.js models kept in the mobs and shots Maps. World and Sound are each one object whose methods are mixed in from four part classes, such as WorldBuild and SoundAmbient. Themes, looks, views and effects other than those four have no object of their own: they are modules of functions and state.

4. Plugin slots

A plugin is { name, provides, setup(host) }. setup gets host.events, host.three (the game's own three.js) and host.kit (the plugin API, so a one-file plugin needs no imports), host.provide(service, impl) and host.add(list, item). Filling a slot not listed in provides is refused, and a plugin whose setup throws is logged and left out. Source: src/core/plugins.ts. A plugin built into the game imports from plugin.ts ("craftax-3d/plugin": the types, block ids, the tile painter's helpers, creature parts, HUD icons, orient) and nothing else of the game; tools/check-plugins.ts, part of npm run check, fails any other import.

5. Components

Boot and setup

One config file sets up a copy of the game: its home site (the Research screen and menus link there) and its plugins. src/config.ts reads it and registers the plugins on import, so both pages import it first. js/main.ts then boots: the player's own plugins, the server or local engine, /api/meta, the HUD, the themes, then the first world. The start menu carries the Shellcaster credit (index.html).

Key files
craftax.config.ts, src/config.ts, js/main.ts, index.html, replay.html, vite.config.ts, src/page-url.ts, js/build.ts, tools/runtime-files.ts
Depends on
Everything: importing js/main.ts pulls every part in, in order.
Extension points
CRAFTAX_CONFIG (a host's own config), CRAFTAX_OUT (build elsewhere), CRAFTAX_TUNNEL (phone via ngrok), the craftax-3d/… import alias for plugins, VITE_SHIPPED=1 (drops debug switches like ?god).

Plugin core

The registry (two services, seven lists), the typed event bus handed to plugins, and the plugins a player adds by hand: an https address or a .js file, saved per player and loaded at boot before the first world is built. Never from a link; ?noplugins boots without them.

Key files
src/core/plugins.ts, src/core/events.ts, src/core/user-plugins.ts
Depends on
three, the theme types
Extension points
All nine slots (table above). Events: ready, state, step, screen.

Game core

The game's state (meta, the state, the HUD, the views, creatures and shots, keys held, the server API), apply(s): a new state against the old one and everything that follows from the difference, and frame(now): the clock, the frame-rate meter, moving and drawing everything. Shared bits (sound, DOM lookup, action ids, eye height) and the data shapes live here too.

Key files
src/core/game.ts, apply.ts, frame.ts, shared.ts, types.ts, mixin.ts
Depends on
Nearly every other part (effects, render, UI, input, themes, looks, views) and the engine bridge
Extension points
None directly; plugins reach it through slots and events.

Engine bridge

The craftax-wasm engine (bit-exact with JAX Craftax) runs in the tab and answers the same /api/… calls a game server would, so the game plays it unchanged. It records every op for replays, places a scene's set pieces into a new world, and runs the bot. js/net.ts keeps the platform plumbing: which server, which world, the world and server lists (?server=local, ?watch=).

Key files
js/local.ts, js/net.ts, engine/ (built from craftax-wasm, git-ignored, copied by tools/runtime-files.ts), src/core/types.ts (CraftaxGame, the state's shape)
Depends on
engine, bots, set pieces (src/scenes/place.ts), telemetry
Extension points
bot sources may observe something other than the packed observation; CRAFTAX_WASM points at another engine checkout.

Bots

The playable models are listed in craftax-agents' models.json, copied to public/models.json by tools/runtime-files.ts (the first is the default); each loads lazily in its own worker, only once picked, and runs as ONNX in onnxruntime-web: observation and action mask in, an action out (greedy or sampled). The bot panel's neuron brain shows the action probabilities; the Research screen lists the papers and the agents.

Key files
js/agent.ts, js/agent-worker.ts, js/brain.ts, js/research.ts, public/models.json, public/agent/ort/ (fetched at build)
Depends on
onnxruntime-web, src/core
Extension points
Slots bot (other kinds of bot, each in its plugin's worker) and brainView. New ONNX agents: an entry in craftax-agents' models.json.

World building

The current floor's map as blocks: one mesh per material, rebuilt chunk by chunk when the map, items or light change. The World class is split over several modules and mixed together: terrain (column heights, ground, portcullises), build (the meshes), shapes (loose pieces, the crosshair's raycast), light (torch and lava light, fountains).

Key files
src/world/core.ts, build.ts, terrain.ts, shapes.ts, light.ts, geo.ts, blocks.ts; js/world.ts keeps the import path
Depends on
themes (the most-used import), block textures, shading, set pieces
Extension points
Theme.tile, shape, decorate, crown; set pieces' covers, paved, draw, beyond, solid.

Rendering and shading

The WebGL renderer, scene, camera and sky (sun, moon, stars, clouds); one shader for blocks, water, glow and creatures that ray-traces the floor's voxel grid for shadow and sky light, adds block light, waves and the sun's glint, and outputs HDR for bloom and filmic tone mapping. Also the first-person arm and tool, creatures and their health bars, the player's pose, aiming, and graphics quality.

Key files
src/render/scene.ts, arm.ts, entities.ts, player-pose.ts, quality.ts, targeting.ts, src/render/shading/, js/shading.ts, js/models.ts, js/clouds.ts
Depends on
three, world, themes, looks, effects
Extension points
Theme.creatures, player, sky, grass; the shader blends two themes' atlases per tile.

Textures and icons

No image files for the 3D blocks: every tile is painted by code into one atlas (with lava's frames), plus a line-drawing atlas for the laser and phosphor looks. The HUD's pixel icons and the item registry (hotbar slots, recipes, spells, armor) live beside them.

Key files
src/resources/blocks/ (paint.ts, atlas.ts, outline-atlas.ts, painters/), src/resources/items/; js/textures.ts keeps the import path
Depends on
themes, world block ids
Extension points
Theme.paint (repaint existing tiles), tiles (new tiles with outlines), icons; SetPieces.tiles.

Looks

How the world is rendered (M): color, laser (red outlines over dark, from the surface ids the scene renders), phosphor (green), and any look a plugin adds (noir and pixel come as examples). Each look draws every view, the classic 2D view in Craftax's original art unless it has a picture of its own. Owns the post-processing composer and bloom, the fade between looks, each frame's render in its look, and each look's own HUD styles and effects (phosphor's shockwaves and gravestone in characters).

Key files
src/looks/types.ts (the Look interface), registry.ts (the looks in M's order), looks.ts (state and switches), render.ts, shared/outline-pass.ts (the outline pass both line looks use), shared/outline.css (the HUD and menus both line looks share, under body.outline), one folder a look with its code and css (color/, laser/, phosphor/: code art, shockwaves, the gravestone, the caption), js/art2d.ts (the original 2D renderer, ported)
Depends on
render, effects, shading
Extension points
Slot look (a new look with its own button), slot lookView (how a look draws some views: a post pass in 3D, or its own picture in the classic view; doc/looks.md); Theme.classic (a theme's own 2D picture); Theme.weather gets the look to draw outlines only.

Views

Where the camera is: first person, third person, the classic 2D view and the 3/4 overhead (C, V, B), with the flights between them, quakes and jolts. Also the memory strip's two canvases beside the classic view, which only show when a plugin brings a memory view.

Key files
src/views/views.ts, camera.ts, memory.ts
Depends on
looks, render, input, effects, UI
Extension points
Slots lookView (a look's renderer for a view) and memoryView.

Themes

What the world is drawn as (T), never what it is: the engine, bots, recordings and replays are the same under any theme. Repaints the atlas with the theme's tiles, asks the theme tile by tile for faces, heights and decorations, morphs crowns and creatures as a wave runs out from your tile, and eases in its sky, fog and weather. Includes the Settings picker and on-screen names.

Key files
src/themes/types.ts (the interfaces), state.ts, transition.ts, atlas.ts, blocks.ts, crowns.ts, creatures.ts, creature-morph.ts, sky.ts, weather.ts, names.ts, draw.ts, ui.ts; guide: doc/themes.md
Depends on
world, textures, render, sound (theme sounds)
Extension points
Slot theme. Theme fields: id, label, default, transition (wave or fade), paint, tiles, tile(), shape(), decorate(), crown(), icons, names, bits, grass, creatures, player, sky, weather(), classic(), sounds.

Set pieces (scenes)

Real content a scene writes into a new world: each floor is read as generated and handed to the scene's place(); its writes go into the engine's own snapshot, so from then on they are the game (saved, recorded, replayed). recognize() finds a set piece again from the map alone. A scene keeps its worlds apart from the player's own.

Key files
src/scenes/active.ts (which scene, ?scene=), place.ts, orient.ts (turning a layout to a side of the map)
Depends on
themes (types, Draw), the engine snapshot via js/local.ts
Extension points
Slot setPieces: id, label, default, tiles, place(), recognize(); a Placement has data, writes, moves, covers(), paved(), draw(), beyond(), solid(), fog.

Effects

The game's moments, played out on top of the state: felling a tree, dust bursts and dying creatures, hits and knockback, chests opening and low-need warnings, dying (falling, sinking, lava), hanging over lava's edge, fireballs and iceballs, the Necromancer, the victory and the portal tunnel, and the ?god / ?debug tools.

Key files
src/effects/ (chest, death, god, hang, hits, necromancer, shots, tunnel, victory), js/fell.ts, js/fell-types.ts
Depends on
core, render, UI, looks, shading
Extension points
Theme.bits (leaf and grass colors of the loose bits).

Input

Turns keys, mouse and touch into one Craftax action per tick: every key's meaning, hold to act, looking and turning, the touch pad with Use and Sleep, what a click aims at, walking to a clicked target (digging through, the nearest shore), and the tool picked for the action.

Key files
src/input/intent.ts, keyboard.ts, pointer.ts, touch.ts, aim.ts, targets.ts, pathing.ts
Depends on
core (the API), UI, render, world
Extension points
None.

HUD, UI and screens

The HUD (status bars, hotbar, gear, achievement toasts, the E screen for inventory, crafting, potions and magic), flashed messages and hints, touch button layout, and the screens: Settings and its tabs, options, help, the inventory, other worlds and My Worlds, the death screen's retry, screenshots and thumbnails, and the pixel-font titles.

Key files
src/ui/hud/, src/ui/screens/, src/ui/snapshots.ts, js/hud.ts, js/pixeltitle.ts, src/styles/game.css, phone.css
Depends on
core, render, input, looks, the engine bridge, item registry
Extension points
Slot brainView (bot panel); Theme.names and icons change what the HUD shows.

Sound

Mostly synthesized with Web Audio (tones and filtered noise for steps, chopping, mining, combat, ambience), plus CC0 recorded clips for creature voices. Positioned sounds pan and fade with distance. A gate thins sounds when a fast bot plays, so the browser's audio never floods. Replay videos render the sound offline.

Key files
src/sound/core.ts (the Sound class), world.ts, creatures.ts, events.ts, ambient.ts, gate.ts, common.ts; js/sound.ts; public/sounds/
Depends on
themes (theme sounds), core events
Extension points
Theme.sounds: replace or silence any named effect ("moo", "hit:cow"…), routed by gate.ts.

Replay: recording and the replay page

A recording is the engine's whole state where it began (an 84 KB snapshot), every op made after it with its time, and the camera ten times a second; the deterministic engine plays it back exactly. The replay page plays a recording in the game page (an iframe), trims it, sets camera keyframes, and shares it as a file, an MP4 (WebCodecs + mp4-muxer), a screenshot, or a link.

Key files
js/record.ts, src/replay/recording.ts, js/replay-page.ts, src/replay/page/ (open, keyframes, transport, side, share, video), js/film.ts, replay.html, vendor/mp4-muxer/, src/styles/replay.css
Depends on
engine bridge (ops), views, looks, themes, UI
Extension points
Slot replayStore (share by link, short links, embeds).

Telemetry

Decides what happened (starts, achievements, floors, the bot taking over, the end, each step's actor and action) and keeps per-game totals in localStorage. Where it goes is a plugin's choice. Never sent with debug flags, when Settings' "Send anonymous play statistics" is off, or under Global Privacy Control.

Key files
js/telemetry.ts
Depends on
core
Extension points
Slot telemetry (one provider).

6. The bundled plugins

Winter plugins/winter

A theme: snow lying on the overworld and falling from a pale sky, fir crowns with snow on their layers, drifts round a few lone trees, a light dusting on ore, cows as reindeer (name, model, sounds; one in ten with a glowing red nose), zombies in torn flannel. Only the overworld; near lava the snow has melted.

Fills
theme (uses paint, tiles, tile, decorate, crown, creatures, names, sounds, sky, weather)
Install
plugins: [winter()]; winter({ default: true }) starts players in it.

Ruins plugins/ruins

A theme: the overworld's rock and ore drawn as ruined college stonework under a soft grey sky. Broken walls on an old building's lines, rubble elsewhere, many kinds of weathered stone; each ore its own recognizable piece of the old buildings. Its building-stone painters are shared with Oxford.

Fills
theme
Install
plugins: [ruins()]; ruins({ default: true }).

Tropical plugins/tropical

A theme: palm trees (eight, reused and turned; tall, middle and short), beaches fading into the grass over four tiles, volcanic rock and red clay on the overworld, cows as pigs (recorded CC0 grunts and squeals), skeletons in grass skirts, zombies in faded Hawaiian shirts and board shorts, you in shorts.

Fills
theme (uses tiles, paint, tile, trunk, crown, crownPick, grassAt, flowers, creatures, player, names, sounds)
Install
plugins: [tropical()]; tropical({ default: true }).

University plugins/university

A scene pack with set pieces: ?scene=oxford puts Radcliffe Square on an edge of the map (the Camera half past the edge, its lawn, railing and avenue written into the engine's map); ?scene=campus a college campus seen across the water. Built from block models turned to the first side with no ladder.

Fills
setPieces (imports Ruins' tiles)
Install
plugins: [university(), ruins()]; university({ default: true }).

Autumn examples/plugins/autumn.js

A sample a player adds by hand (Settings → World → Add plugin…), as a file or by its address: orange, red and gold trees, dry grass, a warmer sky, falling leaves. One plain file with nothing to import: it uses host.three.

Fills
theme
Loaded by
src/core/user-plugins.ts, not the config.

craftax-crystal sibling repo

Crystal players: trained optical glass, simulated in the browser on WebGPU by the neuralcrystal package. Listed in a host's config, never built into the open game.

Fills
bot (crystals in the picker, own worker and frame), lookView (the crystal's picture: laser in the classic view), brainView, memoryView
Imports
craftax-3d/… (peer dependency, resolved to ../craftax-3d)

7. Loose ends found while mapping

  • The view slot is declared but never read. It's in src/core/plugins.ts's list table (typed unknown); no module calls listed("view").
  • Game events are declared but never emitted. GameEvents (ready, state, step, screen) is handed to plugins as host.events, but nothing in src/ or js/ calls events.emit, so a plugin listening hears nothing.
  • public/servers.json lists "NeuralCrystal (this machine)" at localhost:8790.
